# CHZZK Chat Archive

[`kimcore/chzzk`](https://github.com/kimcore/chzzk)를 이용해 CHZZK 채팅을 방송별로 저장하고, 웹에서 파일과 참여자 현황을 탐색하는 Docker 프로토타입입니다.

## 제공 기능

- 스트리머별 채팅 수집
- 방송 시작 시 `*_live.jsonl`, 방송 종료 후 `*_off.jsonl`로 분리
- `NID_AUT`, `NID_SES`를 별도 JSON 파일로 관리
- 로그인/로그아웃이 있는 웹 파일 탐색기
- 채팅 저장 경로 아래로 제한된 목록 조회, 다운로드, 삭제
- 사용자 ID 기준 중복 제거 참여자 현황
- 닉네임/사용자 ID 및 메시지 내용 필터
- 항목별·일별 구조화 운영 로그와 전용 웹 탐색·분석
- 7일 초과 운영 로그의 GZIP 자동 압축 보존
- 웹 설정 화면에서 스트리머 추가·수정·삭제 및 수집 활성화
- 전역 방송 상태 확인 주기와 스트리머 간 순차 스캔 간격 설정
- 방종 후 채팅 무제한 수집 또는 사용자 지정 시간 제한
- 웹에서 `NID_AUT`, `NID_SES` 갱신 또는 삭제
- 쿠키 저장 전 CHZZK 로그인 사용자 정보 API로 유효성 검증
- 최초 실행 시 웹에서 관리자 계정 생성
- 스트리머별 저장, 삭제 확인 및 체크박스 선택 일괄 삭제

> `chzzk`는 비공식 API 라이브러리입니다. CHZZK 변경으로 수집이 중단될 수 있으며, 서비스 약관과 개인정보 관련 법령을 확인해 개인적이고 정당한 범위에서 사용하세요.

## 빠른 시작

1. 배포용 Compose 파일을 내려받습니다.

   ```bash
   mkdir chzzk-chat-archive
   cd chzzk-chat-archive
   curl -fsSLO https://raw.githubusercontent.com/PCBiS/chzzk-chat-archive/main/compose.yaml
   ```

2. 공개 GHCR 이미지를 내려받아 실행합니다.

   ```bash
   docker compose pull
   docker compose up -d
   ```

3. `http://localhost:3000`을 열면 최초 관리자 계정 생성 화면이 표시됩니다.

4. 관리자 아이디와 6자 이상의 비밀번호를 생성합니다. 생성 후 로그인 화면으로 돌아가며 새 계정으로 로그인할 수 있습니다.

5. **설정** 화면에서 스트리머와 CHZZK 로그인 쿠키를 입력합니다. 행별 **저장** 또는 하단의 전체 저장 버튼으로 즉시 크롤러에 반영됩니다. 쿠키는 하단 **설정 저장 및 적용**을 눌렀을 때 로그인 상태 검증에 성공해야 저장됩니다.

이미지는 `ghcr.io/pcbis/chzzk-chat-archive:latest`에서 제공되며 `linux/amd64`, `linux/arm64`를 지원합니다. 업데이트할 때는 `docker compose pull && docker compose up -d`를 실행하세요.

쿠키가 없어도 공개 채팅은 동작할 수 있으나 인증이 필요한 채널에서는 제한될 수 있습니다. 쿠키 원문은 로그인한 관리자 설정 화면에서 읽기 전용으로 표시되며, 응답은 캐시하지 않습니다. 설정 자체는 Docker의 `chzzk-config` 볼륨에 보관됩니다.

운영 로그는 `/logs`에 `system`, `crawler`, `auth`, `settings`, `files` 항목별로 저장됩니다. 한국 날짜 기준으로 매일 새 JSONL 파일을 사용하고 7일을 초과한 파일은 `.jsonl.gz`로 압축합니다. 웹의 **운영 로그** 메뉴에서만 목록, 다운로드, 레벨·내용 필터와 이벤트 집계를 확인할 수 있습니다. 쿠키, 비밀번호 및 채팅 본문은 운영 로그에 기록하지 않습니다.

채팅 원본은 계속 JSONL로 보존하며, 웹 분석을 위한 SQLite 증분 인덱스는 `/data/.chzzk-index/chat.sqlite`에 자동 생성됩니다. 시작할 때 기존 JSONL의 새 부분만 반영하고 수집 중인 채팅은 저장 직후 인덱싱합니다. 이 내부 경로는 웹 파일 탐색기·다운로드·삭제 API에 노출되지 않습니다.

## 저장 구조

```text
data/
└── 스트리머명/
    ├── 260730_08h07m54s_스트리머명_live.jsonl
    └── 260730_17h23m31s_스트리머명_off.jsonl
```

파일 시각은 한국 표준시(`Asia/Seoul`) 기준입니다. 방송 종료를 감지하면 라이브 파일을 닫고, 감지 시각으로 이름을 만든 `*_off.jsonl`에 방종 후 채팅을 이어서 기록합니다. 기존 구조로 저장된 파일은 자동 이동하지 않으며 새 수집 파일부터 위 구조가 적용됩니다.

각 줄은 독립적인 JSON 객체입니다. 주요 필드는 `messageAt`, `streamer`, `broadcast`, `event`, `user`, `message`입니다.

## 전역 수집 설정

웹의 **설정 → 전역 수집 설정**에서 모든 스트리머에 공통 적용되는 값을 변경할 수 있습니다.

- 방송 상태 확인 주기: 기본 60초
- 스트리머 간 스캔 간격: 기본 20초. 상태 요청은 이 간격으로 한 명씩 순차 실행됩니다.
- 방종 후 수집 제한: 기본 무제한이며 필요하면 분 단위 정수로 제한을 설정할 수 있습니다.

모든 분·초 입력값은 정수만 허용합니다. 상태 확인 주기를 60초 미만 또는 스트리머 간 간격을 20초 미만으로 설정하면 CHZZK의 IP 차단 위험 경고와 저장 확인창이 표시됩니다. 스트리머가 많으면 요청 간격을 지키기 위해 한 스트리머의 실제 재확인 주기가 설정값보다 길어질 수 있습니다.

스트리머는 하나의 전역 순차 스캔 대기열에서 관리됩니다. 새 스트리머를 저장하거나 설정을 다시 적용해도 기존 스트리머별 마지막 스캔 시각과 마지막 전역 요청 시각을 유지하므로, 새 요청은 직전 요청으로부터 설정된 스캔 간격이 지난 뒤 대기열 순서에 따라 실행됩니다.

## 보안 경계

- 웹 파일 API는 `/data` 아래의 `.jsonl`, `.txt`만 취급합니다.
- `..`, 절대 경로, 심볼릭 링크를 이용한 경로 이탈을 거부합니다.
- 파일 업로드 기능은 제공하지 않습니다.
- 삭제는 JSONL/TXT 채팅 파일과 빈 폴더에만 허용하며, 현재 수집 중인 파일은 삭제할 수 없습니다.
- 설정/쿠키 파일은 웹 탐색기에 노출되지 않습니다.
- SQLite 분석 인덱스가 들어 있는 `/data/.chzzk-index` 내부 경로도 웹에서 접근할 수 없습니다.
- 운영 로그 API는 `/logs` 안의 `.jsonl`, `.jsonl.gz` 파일만 조회·다운로드·분석합니다.
- 컨테이너는 non-root, read-only root filesystem, capability 제거로 실행됩니다.
- 관리 화면을 인터넷에 직접 노출하지 말고 HTTPS 리버스 프록시나 VPN 뒤에서 사용하세요.

## 현재 프로토타입의 한계

- 세션은 메모리에 저장되므로 컨테이너 재시작 시 로그아웃됩니다.
- 방송 종료 시점에 프로세스가 꺼져 있으면 과거 방종 후 채팅을 복구하지 못할 수 있습니다.
