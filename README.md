# CHZZK Chat Archive

[`kimcore/chzzk`](https://github.com/kimcore/chzzk)를 이용해 Chzzk 채팅을 방송별로 저장하고, 웹에서 채팅 참여자 현황을 분석할 수 있는 애플리케이션입니다.

이 프로젝트의 초기 프로토타입 설계, 구현 및 문서 작성에는 OpenAI Codex를 사용했습니다.

버전별 변경 내역은 [GitHub Releases](https://github.com/PCBiS/chzzk-chat-archive/releases)에서 확인하세요. [0.7.1 릴리스 노트](https://github.com/PCBiS/chzzk-chat-archive/releases/tag/v0.7.1).

## 제공 기능

- 스트리머별 채팅 수집
- AI 도구가 채팅 기록을 직접 조회하는 읽기 전용 MCP 엔드포인트(`/mcp`)와 접근 키 관리
- 방송 시작 시 `*_live.jsonl`, 방송 종료 후 `*_off.jsonl`로 분리
- `NID_AUT`, `NID_SES`를 별도 JSON 파일로 관리
- 로그인/로그아웃이 있는 웹 채팅 기록 보기
- 채팅 저장 경로 아래로 제한된 목록 조회, 다운로드, 삭제
- 사용자 ID 기준 중복 제거 참여자 현황
- 닉네임/사용자 ID 및 메시지 내용 필터
- 채팅 기록 보기: 최근 3일은 목록으로, 그 이전 방송은 달력에서 날짜를 골라 찾기(방송 시작 시각 기준, 압축 여부와 무관)
- 목록에서 방송을 누르면 바로 채팅 분석으로 이동
- 선택한 방송의 채팅 전체를 한 번에 불러와 스크롤에 맞춰 표시
- 채팅의 `{:이름:}` 이모티콘을 이미지로 표시. 이미지는 `data/.chzzk-emoji`에 저장하고 주 1회 누락·실패분을 보충
- 항목별·일별 구조화 운영 로그와, 기간·분류·수준으로 거르는 시간순 로그 화면(주기적인 방송 상태 확인은 횟수만 표시)
- 7일 초과 운영 로그의 GZIP 자동 압축 보존
- 수집 완료 후 7일이 지난 채팅 원본의 gzip9 압축과 압축 해제 없는 검색
- 웹 설정 화면에서 스트리머 추가·수정·삭제 및 수집 활성화
- 전역 방송 상태 확인 주기와 스트리머 간 순차 스캔 간격 설정
- 방종 후 채팅 무제한 수집 또는 사용자 지정 시간 제한
- 웹에서 `NID_AUT`, `NID_SES` 갱신 또는 삭제
- 쿠키 저장 전 CHZZK 로그인 사용자 정보 API로 유효성 검증
- 브라우저 확장(Get cookies.txt 등)으로 내보낸 쿠키 파일에서 `NID_AUT`·`NID_SES`를 자동 추출(파일은 브라우저에서만 읽음)
- 저장된 쿠키를 하루 한 번 자동 확인하고, 만료되면 화면 상단과 운영 로그에 표시. 설정 화면의 **지금 확인**으로 즉시 확인
- 최초 실행 시 웹에서 관리자 계정 생성
- 스트리머별 저장, 삭제 확인 및 체크박스 선택 일괄 삭제

> [`kimcore/chzzk`](https://github.com/kimcore/chzzk)는 비공식 API 라이브러리입니다. Chzzk의 내부 API 변경으로 언제든지 수집이 중단될 수 있으며, 서비스 약관과 개인정보 관련 법령을 확인해 개인적이고 정당한 범위에서 사용하시기 바랍니다.

## 빠른 시작

### 실행

1. 배포용 Compose 파일을 내려받습니다.

   ```bash
   mkdir chzzk-chat-archive
   cd chzzk-chat-archive
   curl -fsSLO https://raw.githubusercontent.com/PCBiS/chzzk-chat-archive/main/compose.yaml
   ```

2. 공개 GHCR 이미지를 내려받아 실행합니다.

   ```bash
   docker compose pull
   docker compose up -d
   ```

3. `http://localhost:3000`을 열면 최초 관리자 계정 생성 화면이 표시됩니다.

4. 관리자 아이디와 6자 이상의 비밀번호를 생성합니다. 생성 후 로그인 화면으로 돌아가며 새 계정으로 로그인할 수 있습니다.

5. **설정** 화면에서 스트리머와 CHZZK 로그인 쿠키를 입력합니다. 행별 **저장** 또는 하단의 전체 저장 버튼으로 즉시 크롤러에 반영됩니다. 쿠키는 하단 **설정 저장 및 적용**을 눌렀을 때 로그인 상태 검증에 성공해야 저장됩니다.

### 포트 바인딩 설정

기본 `compose.yaml`은 다음과 같이 관리 화면을 호스트의 로컬 루프백 주소에만 공개합니다.

```yaml
ports:
  - "127.0.0.1:3000:3000"
```

이 설정은 같은 호스트에서 실행되는 리버스 프록시를 통해 접속하거나, 해당 호스트에서만 관리 화면을 열 때 적합합니다. 다른 PC나 별도 호스트의 리버스 프록시에서 직접 접속해야 한다면 배포 환경에 맞게 바인딩 주소를 변경해야 합니다.

예를 들어 모든 네트워크 인터페이스에서 3000번 포트를 열려면 다음과 같이 변경할 수 있습니다.

```yaml
ports:
  - "3000:3000"
```

특정 LAN 주소에서만 열려면 `"192.168.0.10:3000:3000"`처럼 실제 호스트 주소를 지정할 수 있습니다. 외부 인터페이스에 포트를 공개할 경우 방화벽 접근 범위를 제한하고 HTTPS 리버스 프록시 또는 VPN 뒤에서 사용하는 것을 권장합니다. 설정을 변경한 뒤에는 `docker compose up -d`를 다시 실행하세요.

이미지는 `ghcr.io/pcbis/chzzk-chat-archive:latest`에서 제공되며 `linux/amd64`, `linux/arm64`를 지원합니다. 업데이트할 때는 `docker compose pull && docker compose up -d`를 실행하세요.

업데이트 전 설정·채팅 자료·압축 상태 DB·검색 DB의 일관된 백업을 보관하세요. 컨테이너를 재생성하면 메모리 로그인 세션이 종료됩니다. 업데이트별 변경 사항과 호환성 안내는 [Releases](https://github.com/PCBiS/chzzk-chat-archive/releases)를 참고하세요.

쿠키가 없어도 공개 채팅은 동작할 수 있으나 인증이 필요한 채널에서는 제한될 수 있습니다. 쿠키 원문은 로그인한 관리자 설정 화면에서 읽기 전용으로 표시되며, 응답은 캐시하지 않습니다. 설정 자체는 Docker의 `chzzk-config` 볼륨에 보관됩니다.

운영 로그는 `/logs`에 `system`, `crawler`, `auth`, `settings`, `files` 항목별로 저장됩니다. 한국 날짜 기준으로 매일 새 JSONL 파일을 사용하고 7일을 초과한 파일은 `.jsonl.gz`로 압축합니다. 웹의 **운영 로그** 메뉴에서만 목록, 다운로드, 레벨·내용 필터와 이벤트 집계를 확인할 수 있습니다. 쿠키, 비밀번호 및 채팅 본문은 운영 로그에 기록하지 않습니다.

채팅은 JSONL로 수집하고, 웹 분석을 위한 SQLite 증분 인덱스는 `/data/.chzzk-index/chat.sqlite`에 자동 생성됩니다. 수집 중인 채팅은 저장 직후 인덱싱합니다. 내부 경로는 웹 파일 탐색기·다운로드·삭제 API에 노출되지 않습니다.

### 채팅 원본 압축과 열람

다음 방송을 확인해 이전 방송의 수집 완료를 판정하고, 마지막 기록·파일 수정 후 7일이 지난 원본을 gzip9로 압축합니다. 완료 근거가 부족한 파일은 보류합니다.

목록에서 방송을 누르면 채팅 분석 화면이 열립니다. 정상 검색은 SQLite를 사용하므로 압축을 해제하지 않습니다. **압축본**은 gzip 그대로, **JSONL 다운로드**는 전송하면서 해제합니다. 해제본을 디스크에 저장하거나 다시 압축하지 않습니다.

검색 자료가 없으면 분석 화면의 **검색 자료 다시 만들기**를 실행하세요. 압축 상태는 `/data/.chzzk-archive/state.sqlite`, 검색 자료는 `/data/.chzzk-index/chat.sqlite`에 저장됩니다. 백업에는 두 DB와 JSONL·gzip 원본을 함께 포함하세요.

## 저장 구조

```text
data/
└── 스트리머명/
    ├── 260730_08h07m54s_스트리머명_live.jsonl
    └── 260730_17h23m31s_스트리머명_off.jsonl
```

파일 시각은 한국 표준시(`Asia/Seoul`) 기준입니다. 방송 종료를 감지하면 라이브 파일을 닫고, 감지 시각으로 이름을 만든 `*_off.jsonl`에 방종 후 채팅을 이어서 기록합니다. 방종 후 수집 중에 앱이 재시작되면 직전 방송 정보로 새 `*_off.jsonl`을 만들어 수집을 이어 갑니다(파일 이름은 재개 시각). 0.7.1 이전에는 UTC로 동작하는 서버에서 라이브 파일 이름이 방송 시작보다 9시간 늦게 붙었습니다. 0.7.1은 처음 시작할 때 이런 파일(압축본 포함)의 이름을 기록 안의 방송 시작 시각으로 고치고, 압축 상태와 검색 DB의 경로도 함께 옮깁니다. 기존 구조로 저장된 파일은 자동 이동하지 않으며 새 수집 파일부터 위 구조가 적용됩니다.

각 줄은 독립적인 JSON 객체입니다. 주요 필드는 `messageAt`, `streamer`, `broadcast`, `event`, `user`, `message`입니다.

## 전역 수집 설정

웹의 **설정 → 전역 수집 설정**에서 모든 스트리머에 공통 적용되는 값을 변경할 수 있습니다.

- 방송 상태 확인 주기: 기본 60초
- 스트리머 간 스캔 간격: 기본 20초. 상태 요청은 이 간격으로 한 명씩 순차 실행됩니다.
- 방종 후 수집 제한: 기본 무제한이며 필요하면 분 단위 정수로 제한을 설정할 수 있습니다.

모든 분·초 입력값은 정수만 허용합니다. 상태 확인 주기를 60초 미만 또는 스트리머 간 간격을 20초 미만으로 설정하면 CHZZK의 IP 차단 위험 경고와 저장 확인창이 표시됩니다. 스트리머가 많으면 요청 간격을 지키기 위해 한 스트리머의 실제 재확인 주기가 설정값보다 길어질 수 있습니다.

스트리머는 하나의 전역 순차 스캔 대기열에서 관리됩니다. 새 스트리머를 저장하거나 설정을 다시 적용해도 기존 스트리머별 마지막 스캔 시각과 마지막 전역 요청 시각을 유지하므로, 새 요청은 직전 요청으로부터 설정된 스캔 간격이 지난 뒤 대기열 순서에 따라 실행됩니다.

## 보안 경계

- 웹 파일 API는 `/data` 아래의 `.jsonl`, `.txt`만 취급합니다.
- `..`, 절대 경로, 심볼릭 링크를 이용한 경로 이탈을 거부합니다.
- 파일 업로드 기능은 제공하지 않습니다.
- 삭제는 JSONL/TXT 채팅 파일과 빈 폴더에만 허용하며, 현재 수집 중인 파일은 삭제할 수 없습니다.
- 설정/쿠키 파일은 웹 탐색기에 노출되지 않습니다.
- SQLite 분석 인덱스가 들어 있는 `/data/.chzzk-index` 내부 경로도 웹에서 접근할 수 없습니다.
- 운영 로그 API는 `/logs` 안의 `.jsonl`, `.jsonl.gz` 파일만 조회·다운로드·분석합니다.
- 컨테이너는 non-root, read-only root filesystem, capability 제거로 실행됩니다.
- 관리 화면을 인터넷에 직접 노출하지 말고 HTTPS 리버스 프록시나 VPN 뒤에서 사용하세요.

## 세션 보안 정책

- 로그인 쿠키는 만료 시각을 저장하지 않는 브라우저 세션 쿠키입니다. 일반적으로 브라우저를 종료하면 로그인 쿠키가 삭제됩니다.
- 서버 세션은 의도적으로 메모리에만 저장하므로 컨테이너를 재시작하면 모든 관리자가 로그아웃됩니다.
- 공용 PC에서는 브라우저 종료에만 의존하지 말고 관리 화면의 로그아웃 버튼을 사용하세요.

## 현재 프로토타입의 한계

- 프로세스가 꺼져 있던 동안의 채팅은 복구할 수 없습니다. 다시 켜지면 연결 직후 최근 채팅 50개만 받습니다.

## AI 연결 (MCP)

Claude 같은 AI 도구가 저장된 채팅을 직접 조회할 수 있도록 [Model Context Protocol](https://modelcontextprotocol.io) 엔드포인트를 제공합니다.

1. **설정 → AI 연결 (MCP)** 에서 접근 키를 발급합니다. 키는 발급 직후 한 번만 표시되고, 서버에는 해시만 저장됩니다.
2. AI 도구에 주소 `https://<호스트>/mcp` 와 헤더 `Authorization: Bearer <키>` 를 등록합니다. Claude Code 예시:

   ```bash
   claude mcp add --transport http chzzk-chat https://<호스트>/mcp --header "Authorization: Bearer <키>"
   ```

제공 도구는 모두 조회 전용입니다.

| 도구 | 내용 |
| --- | --- |
| `list_broadcasts` | 기간·스트리머별 방송 기록 목록(제목, 채팅 수, 참여자 수) |
| `chat_activity` | 시간대별 채팅량과 가장 활발했던 구간 |
| `get_chat` | 한 기록의 채팅을 시간 구간·참여자·단어로 걸러 `[시각] 닉네임: 내용` 형식으로 읽기 |
| `search_chat` | 여러 방송에 걸친 단어·닉네임 검색 |
| `top_chatters` | 참여자 순위와 채팅·후원·구독 건수 |

- 시각은 모두 한국 시간입니다. 사용자 ID 원문과 원본 `extras`는 내보내지 않습니다.
- 키로는 설정 변경, 삭제, 다운로드를 할 수 없습니다. 쓰지 않는 키는 설정 화면에서 폐기하세요.
- 조회한 채팅은 연결한 AI 서비스로 전송됩니다. 신뢰하는 도구에만 키를 주고, 엔드포인트는 내부망이나 인증된 프록시 뒤에 두세요.
